## 最快的凭据配置：API Key

在和风控制台开通项目与所需 API 权限，创建 API Key，取得该账号专属 API Host。在本机 `server/.env` 或服务器 `deploy/.env` 填写：

```dotenv
QW_HOST=你的专属域名.qweatherapi.com
QW_API_KEY=你的和风APIKey
```

Host 只填控制台给出的完整域名，不带 `https://`、端口或路径。使用专属域名，不使用旧的 `api.qweather.com` 公共域名。保存后重启服务；域名示意不能直接使用。

如果 API Key 已填写，优先使用它；不要同时保留不需要的旧凭据。需要开通的服务是小时天气、分钟降水和天气预警。某一服务无权限不会阻塞其他成功结果，响应 `errors` 会说明对应失败类别。

普通用户登录随变即可，无需自己的和风账号。Key 不写入 APK、不提交 Git、不放 URL 查询参数。后端使用 `X-QW-Api-Key` 请求头。

## 使用 JWT 时的配置

如团队选择官方推荐的 JWT，清空 `QW_API_KEY`，配置：

```dotenv
QW_HOST=控制台的专属域名
QW_DEVELOPER_ID=开发者ID
QW_PROJECT_ID=项目ID
QW_KEY_ID=上传公钥后得到的凭据ID
QW_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n私钥内容\n-----END PRIVATE KEY-----"
```

私钥必须是 Ed25519 PEM，只将公钥上传和风控制台。代码支持实际多行 PEM 或上述字面量 `\n`。JWT 包含 `iss/sub/iat/exp`，Header 包含 `kid`；有效期一小时，缓存50分钟，开发者／项目／凭据／私钥变化会使用独立缓存。机器系统时间必须正确。

`QW_TIMEOUT_S` 默认 4 秒：单次天气 HTTP 请求的时限。仅网络失败、HTTP 429 或 5xx 重试一次，认证错误不盲目重试。`REFRESH_TIMEOUT_S` 默认 15 秒：整次天气和路线刷新时限，超时取消未完成请求并返回已完成部分。客户端读取超时应覆盖后端时限并留出网络余量。

## 对甲的接口约定

请求地址和已有字段不变：`POST /v1/refresh`，携带随变登录后的 Bearer 令牌。

```json
{
  "plan": "这里应放包含 nodes、edges、loc 的完整计划对象，不能只放 plan_id",
  "now": "2026-11-30T08:00:00+08:00"
}
```

`now` 是带时区的当前刷新时刻。返回保留 `plan_patch/changed/weather`；新增顶层 `errors` 供部分失败提示。

| 返回位置 | 含义 |
|---|---|
| `plan_patch.edges` | 成功刷新的原交通方式路线，含高德 ETA、距离、来源和实际取数时间 |
| `changed` | 数值确有变化的路段 ID；仅取数时间变化不算路线变化 |
| `weather.status` | `ok` 三类天气查询都可用；`partial` 部分可用；`unavailable` 全部不可用 |
| `weather.scope` | 固定为 `origin`，天气仅代表计划起点，不能声称覆盖整条行程 |
| `weather.source/fetched_at` | 主要天气源及其实际取数时间；全失败时为 null |
| `weather.sources` | 小时／分钟／预警各自的来源与取数时间；判定数据新旧时使用对应组件，不能将分钟源时间套到小时规则上 |
| `weather.hourly_forecast_at/hourly_precip_mm` | 未来一小时内的首个小时预报时刻和该时段累计降水量，单位毫米；缺测为 null |
| `weather.precip_from_at/precip_from` | 分钟数据中未来两小时内首个有降水的预报时间及本地 HH:MM；不是精确降雨起始时刻；无可用结果时为 null |
| `weather.bike_available` | false：命中小时降水限制；true：可用小时数据未命中该限制；null：无法确认。true 不代表安全保证 |
| `weather.effects` | 命中的规则效果，`effects_source=default` 和 `rules_version` 区分默认估计与真实天气 |
| `weather.warnings` | 已过滤被替代、取消或明确过期的预警；可能保留 null 起止时间，不伪造有效期 |
| `weather.attributions` | 供应商返回的归因及许可说明，甲展示天气时应保留 |
| `errors` | `field/code` 列表，区分天气认证、超时、无覆盖和路线失败，不回显上游正文或密钥 |

成功刷新路线可以按 ID 合并进原计划后调用 `simulate`。地图路线不直接乘以天气系数，原始 ETA 保持可追溯；天气通过下节的显式开关参与推演，避免反复刷新累积放大。甲端需要显示骑行限制／天气缺失提示，不会自动切换交通方式或代用户执行计划。

天气失败不会清除原路线；失败路段不出现在 `plan_patch.edges`。`precip_from=null` 配合 `status/errors` 才能判断是无降水还是无数据。`weather.scope=origin` 明确限定结果范围，不应用于未来其他日期或远端目的地。

## 官方接口与单位依据

| 用途 | 当前接口 | 输入顺序／数值 |
|---|---|---|
| 逐小时 | `/weather/v1/hourly/{latitude}/{longitude}?hours=24` | 纬度、经度；`precipitation.amount.value` 为时段累计毫米 |
| 分钟降水 | `/v7/minutely/5m?location=longitude,latitude` | 经度、纬度；`precip` 为5分钟累计毫米，不能直接当小时量 |
| 预警 | `/weatheralert/v1/current/{latitude}/{longitude}` | 纬度、经度；`metadata.zeroResult=true` 才是合法无预警结果 |

经纬度按官方接口要求保留两位小数。中国大陆坐标使用 GCJ‑02，与当前高德计划一致；其他地区使用 WGS‑84，本轮高德同城链路不扩展境外规划。小时预报文档没有明确时段起止对应，代码保留原始预报时刻，不据此编造精确的下雨开始时间。

官方依据：[认证](https://dev.qweather.com/docs/configuration/authentication/)、[API Host](https://dev.qweather.com/docs/configuration/api-host/)、[小时预报](https://dev.qweather.com/docs/api/weather/weather-hourly-forecast/)、[分钟降水](https://dev.qweather.com/docs/api/minutely/minutely-precipitation/)、[天气预警](https://dev.qweather.com/docs/api/warning/weather-alert/)、[坐标词汇表](https://dev.qweather.com/docs/resource/glossary/)。

## 天气参与推演：给甲的接入增量

保留原有 `POST /v1/simulate`；不传新字段时仍走原计算，不请求天气。启用天气计算时增加 `use_weather=true` 与带时区的参考时间 `now`：

```json
{
  "plan": "这里放原始完整计划对象，需包含date、路段和地点坐标",
  "depart_min": 510,
  "n": 2000,
  "seed": 42,
  "use_weather": true,
  "now": "2026-11-30T08:00:00+08:00"
}
```

服务器自行读取每条路段起点的小时预报，按蒙特卡洛样本实际开始该路段的时刻选择未来60分钟以内的下一条小时预报。`weather.effects` 不是输入凭据，客户端提交的修正系数不参与计算。原始 `plan` 及高德 ETA 不被修改；重复计算不会累加修正。

这是一种明确的小时采样近似，不能声称小时预报提供了精确的降雨开始／结束时刻，也不代表一条长途路线沿途每处的天气。返回 `weather.scope=each_leg_origin_at_departure`；各路段的天气来源、预报范围与样本覆盖数量在 `weather.sources/coverage` 中提供。默认情境系数标注 `effects_source=default`，不包装成高德实测。

本轮参与概率与时间的规则包括：降雨时步行系数、出租车等车增量、工作日高峰等车增量、骑行与电动自行车受限。户外活动价值减半属于方案排序，尚未接入搜索，不用于伪造概率变化。预警仍由 `/refresh` 提供；天气推演目前使用小时降水，没有把预警文字转换成额外未经定义的时间增量。

| 返回情况 | 甲端处理 |
|---|---|
| `weather.status=applied` 且 `sim` 非空 | 显示天气情境下的概率和出发建议，并展示来源 |
| `weather.status=blocked` | 当前出发时刻有骑行受限样本；查看 `blocked_edges`，提示改方式／改时间，不自动执行 |
| `weather.status=partial/unavailable` 且 `sim=null` | 覆盖不足或数据不可用，不展示一个冒充完整天气评估的概率；提示刷新或明确选择普通推演 |
| `sim.depart_by=null` | 没有找到当前时刻之后、天气完整覆盖且达到目标概率的出发时刻 |
| 受限路径及其后续节点的到达／余量为 `null` | 路线不成立时不显示虚构的正常到达时间 |

天气随时间变化，不满足原有“越早出发越好”的单调假设，因此天气模式的出发建议在有覆盖的未来分钟上倒序逐一核验。当前时刻可能受限，但如果同一天稍后有完整覆盖的可行时段，可以给出稍后的建议；不会推荐过去时刻。普通推演继续使用原二分策略。

`/replan` 的请求与语义本轮保持不变。甲执行改时或换方式后，应对新的完整计划再调用天气推演确认，不应把天气模式的 `sim=null` 直接交给旧的非空结果模型。
