# 乙：现有接口试点验收

日期：2026-11-28。分支：`feature/server-w2-parse`。

当前进度：解析、账号与凭据管理已通过离线回归，DeepSeek／高德的真实 HTTP 解析、推演及重排已通过单场景验证。`refresh`、公网部署和安卓真机联调尚未验收。最新结果见 [DeepSeek 真实联调记录](乙_DeepSeek真实联调记录.md)；下文保留实现前的试点方案和失败基线，不代表当前测试结果。

## 当前范围决定

依据用户最新决定，先实现已有接口，不新增草稿、会话、卡片、取时或定位接口。此前 B/C 设计保留为备选材料，不进入本轮实现。

首轮只接通现有 `POST /v1/parse`，响应保持 `intent / draft_plan / questions` 三个字段。已有 `simulate/replan` 的接口保持不变。`refresh` 在 parse 试点验证后继续，生成、报告、OCR、tick 和搜索算子不因“已有接口”而自动扩入乙本轮任务。

未形成可信计划时返回 `draft_plan: null` 与可操作的文字问题；输入本身不合法时返回 422。此行为不增加端点或响应字段。甲的当前模型能够读取空草案和文字问题，正式联调仍需验证。

## 首轮测试及预期

测试位置：`server/tests/test_parse.py`。外部模型与地图全部打桩，数据为合成测试数据，不消耗真实服务配额。

| 数量 | 场景 | 预期 |
|---|---|---|
| 1 | MOCK 模式 | 返回既有示例，模型和地图零调用 |
| 6 | 空白/空值输入、错误时间、无时区时间、错误城市编码 | 422，外部服务零调用 |
| 1 | 明确日期、地点、方式、到达约束 | 返回 Schema 合法计划，用地图桩的真实数值映射，直接通过现有真实推演 |
| 1 | 缺起点 | 保留意图并追问，无计划，不调用地图 |
| 1 | 出发/到达时间用途不明 | 追问，无计划，不调用地图 |
| 1 | 模型日期或时刻与原话不一致 | 按原话正确修正，或明确追问；不得交付错误计划 |
| 1 | 地理编码失败 | 保留地点原文，无计划、不补造路径 |
| 1 | 路径失败 | 无计划，不用零时长或示例数字充当路线 |
| 1 | 模型失败 | 原有三个响应字段仍可读取，无计划，不调用地图 |
| 1 | parse 日额度为零 | 无计划，模型与地图零调用 |
| 1 | 输入含手机号 | 下游调用和日志不含原号码 |

正常用例固定 `now=2026-11-28T21:00:00+08:00`，原话为“明早8点前到三教，从宿舍出发骑车”，期望日期为 11 月 29 日、最晚到达为 08:00。

本轮地点与路线返回字典是对现有内部网关的试点约定，不是新的公开接口。真实地图返回的鉴权、单位、错误码和多候选处理需要另行适配验证。

## 后续检查点

1. 用户确认本轮测试预期后，实现正常输入到合法计划的最小路径与相应失败处理。
2. 跑本轮测试、LLM 失败测试及已有契约/引擎回归，修正后记录实际输出。
3. 增加时间语料、多候选地点、无效路径数据、跨日配额等边界测试并验证，不把首轮 16 项当成完整交付证明。
4. 真正调用外部服务前确认配置与额度；使用实际返回验证内部适配，不以合成桩结果宣称联网成功。

建立上述失败基线时尚未修改生产实现。此后已实现首轮解析流程；`schema/`、Android 和环境示例文件保持不变。
