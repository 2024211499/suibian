# 甲方主机启动手册

日期：2026-11-29。适用前提：甲已克隆 `feature/server-acceptance`，并收到配置好的 `.env`。本手册以 **Windows + PowerShell + Python 3.12** 为主，目标是在甲自己的电脑运行后端，供自己的 App 使用。接口字段另见[甲方联调交接](甲方联调交接.md)。

当前阶段直接运行 Python 服务即可，**不要求安装 Docker、Redis、PostgreSQL，不要求购买域名**。以下命令不会安装 Android SDK，也不修改 Android 工程。

## 1. 确认目录与配置文件

项目应保留整个仓库，不能只复制 `server/app`。例如：

```text
D:\projects\suibian\
├─ .venv\                     首次安装时创建，不从乙的电脑复制
├─ .state\                    首次运行时自动创建，保存账号等服务端状态
├─ schema\                    必须保留
├─ scripts\
├─ server\
│  ├─ .env                    把收到的配置文件放这里
│  ├─ app\
│  └─ requirements.lock
└─ deploy\
```

打开 PowerShell，只修改下面第一行的项目路径：

```powershell
$Project = 'D:\projects\suibian'
Set-Location -LiteralPath $Project
git branch --show-current
git status --short
Test-Path -LiteralPath '.\server\.env'
Test-Path -LiteralPath '.\schema\plan_graph.schema.json'
```

应看到当前分支 `feature/server-acceptance`，两个 `Test-Path` 都是 `True`。如果工作在已经合并后端的 `main`，也可运行，但先确认包含后端代码。不要为了启动服务强制切换分支、重置或覆盖甲方已有修改。

收到的文件名必须是 `.env`，不能是 `.env.txt`。Windows 资源管理器可打开“显示文件扩展名”确认。文件内容不必粘贴进终端、聊天或 Git。

本手册统一从 **`server` 目录启动**：配置会先读 `server/.env`，再读 `deploy/.env`；同名字段以后者覆盖前者，进程环境变量又会覆盖配置文件。甲只有一份配置时放在 `server/.env`，避免另一份旧 `deploy/.env` 覆盖它。

移机时特别确认：若配置中写死了乙电脑的 `STATE_DIR` 或 `SCHEMA_DIR`，应删去这两项让程序用仓库默认路径，或改为甲电脑实际路径。不要创建指向乙电脑盘符的状态目录。

## 2. 首次安装 Python 依赖

先检查 Python 3.12：

```powershell
py -3.12 --version
```

应输出 `Python 3.12.x`。没有此版本时先安装 Python 3.12，再重开 PowerShell。不要复制乙电脑的 `.venv`，虚拟环境应在甲电脑创建。

在项目根目录执行：

```powershell
Set-Location -LiteralPath $Project
if (-not (Test-Path -LiteralPath '.\.venv\Scripts\python.exe')) {
    py -3.12 -m venv .venv
    if ($LASTEXITCODE -ne 0) { throw '创建 Python 虚拟环境失败' }
}
.\.venv\Scripts\python.exe --version
.\.venv\Scripts\python.exe -m pip install --require-hashes -r .\server\requirements.lock
if ($LASTEXITCODE -ne 0) { throw '依赖安装失败，请先解决错误，不要继续启动' }
.\.venv\Scripts\python.exe -m pip check
if ($LASTEXITCODE -ne 0) { throw '依赖检查失败' }
```

正常应看到 Python 3.12 和 `No broken requirements found.`。此处使用已锁定的运行依赖；无须激活虚拟环境，因此也不需要修改 PowerShell 执行策略。

如果 `.venv` 已存在但并非 Python 3.12，先确认它的用途，再单独建立 3.12 环境；不要直接删除或覆盖不明环境。之后每一步都使用同一个环境中的 Python。

安装依赖需要联网；运行模型、高德和和风也需要甲电脑能访问对应服务。若安装失败，保留错误信息给乙，先不要跳过依赖或随意替换依赖版本。

## 3. 检查运行模式，然后启动

配置好的真实联调文件应包含 `MOCK=0`、`AUTH_REQUIRED=1`。先用只显示非秘密信息的命令检查：

```powershell
Set-Location -LiteralPath (Join-Path $Project 'server')
..\.venv\Scripts\python.exe -c "from app.config import get_settings; s=get_settings(); print({'mock':s.mock,'auth_required':s.auth_required,'schema_exists':s.schema_dir.is_dir(),'state_dir':str(s.state_dir)})"
```

应看到 `mock: False`、`auth_required: True`、`schema_exists: True`，状态路径位于甲的仓库下。此命令不输出 Key 或密码。

然后启动：

```powershell
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 1 --no-proxy-headers --no-access-log
```

看到 `Application startup complete` 和监听 8000 的提示后，**保持此窗口打开**。命令一直占着终端是正常现象。电脑关机、休眠或关闭该终端都会影响服务；这不是已安装的开机自启服务。

`0.0.0.0` 是监听地址，不是 App 应填写的访问地址。第一次 Windows 防火墙询问 Python 网络访问时，为可信的家庭/工作局域网允许“专用网络”；不用为了本地联调开放公共网络。

## 4. 在第二个 PowerShell 窗口检查

```powershell
Invoke-RestMethod 'http://127.0.0.1:8000/v1/health' | ConvertTo-Json -Depth 4
```

真实配置齐全的预期结果：

```json
{
  "status": "ok",
  "version": "0.1.0",
  "checks": {"schema": "ok", "config": "ok"}
}
```

浏览器可访问 `http://127.0.0.1:8000/docs`。直接打开根地址 `/` 显示 `{"detail":"Not Found"}` 是正常的，没有配置首页。

`health` 通过说明程序、Schema 和配置齐全，**不是一次真实模型/地图调用**。若出现 `checks.mode=mock`，目前仍在样例模式；若 `checks.config` 为 `missing:...`，按缺项排查配置，不能只看 `status=ok`。

## 5. 建立甲主机自己的随变账号

**只有 `.env` 不会带来乙主机的用户、密码和会话。** 新主机第一次运行会建立自己的 `.state/auth.sqlite3`。不要继续使用乙服务签发的旧 token，也不要为了沿用测试账号复制整份乙的状态目录。

普通联调用户可在 `/docs` 中展开 `POST /v1/auth/register` → `Try it out`，填写自己决定的用户名和密码。用户名为 3–32 位英文字母、数字或 `_.-`，密码 12–128 字符。注册成功返回 201 与 `access_token`，也可通过 App 的注册页完成。

之后 App 使用 `/v1/auth/login` 登录，给业务请求加 `Authorization: Bearer <access_token>`。令牌有效期 24 小时，过期重新登录。服务器地址从乙改到甲后，客户端应清除旧服务器会话并重新登录。

如果甲要管理供应商配置，另在新终端执行下列**可选**步骤；使用 `.env` 已有 Key 运行普通业务不要求创建管理员：

```powershell
$Project = 'D:\projects\suibian'
Set-Location -LiteralPath (Join-Path $Project 'server')
..\.venv\Scripts\python.exe -m app.admin --username team-admin
```

终端会隐藏输入并要求确认管理员密码。已有管理员的密码不会被此命令覆盖；不要先把同名 `team-admin` 注册成普通用户。

如果 `.env` 已配置 `AUTH_ADMIN_USERNAME/AUTH_ADMIN_PASSWORD`，程序会按配置初始化管理员；两者须同时有效。用户名、密码仍是配置里的值，不存在约定的通用管理员密码。

## 6. 让 App 访问甲的服务

按实际设备选择 Base URL，均保留结尾 `/`：

| App/访问位置 | Base URL |
|---|---|
| 甲电脑本机浏览器或工具 | `http://127.0.0.1:8000/` |
| Android Studio 默认模拟器，后端在同一电脑 | `http://10.0.2.2:8000/` |
| 同一局域网内的实体手机 | `http://甲电脑的局域网IPv4:8000/` |
| 其他网络中的手机/队员 | 甲自己的 HTTPS 公网入口，见下一节 |

`127.0.0.1` 在手机上表示手机自己，不是甲的电脑。`10.0.2.2` 适用于 Android Studio 默认模拟器，实体手机不要使用它。

局域网真机操作：

1. 甲电脑执行 `ipconfig`，找到正在使用的 Wi-Fi/以太网 IPv4，例如 `192.168.1.23`。不要选 VPN、Docker 或未连接网卡。
2. 手机和电脑连接同一局域网，在手机浏览器打开 `http://192.168.1.23:8000/v1/health`（替换为实际 IP）。
3. 浏览器通过后，把 App 的 Retrofit Base URL 改为 `http://192.168.1.23:8000/`，重新构建/安装或按已有配置入口更新地址。
4. 在这个新地址重新登录，然后测试业务接口。App 读取超时建议 40 秒，整次调用 45 秒；旧 8 秒可能不足。

若电脑可访问、手机不可访问，先检查同网、Python 防火墙许可和路由器访客网络隔离。确需手动放行时，可由甲在**管理员 PowerShell**仅放行专用局域网：

```powershell
New-NetFirewallRule -DisplayName 'Suibian API 8000 LAN' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8000 -Profile Private -RemoteAddress LocalSubnet
```

只在缺少相应规则时添加，不要反复执行。停用时可删除该规则：

```powershell
Remove-NetFirewallRule -DisplayName 'Suibian API 8000 LAN'
```

如果手机浏览器能通但 App 提示禁止明文流量，说明是 Android 网络安全配置问题。当前后端分支的 Android 基线允许明文，甲自己的客户端分支可能不同；只在开发配置中处理局域网 HTTP，发布/跨公网访问使用 HTTPS。

## 7. 可选：甲主机生成自己的 HTTPS 入口

甲本人同网测试不需要此步。不同网络访问时，先确保第 4 节本机健康检查通过；甲已安装 `cloudflared` 后，**另开一个终端**运行：

```powershell
cloudflared tunnel --url http://127.0.0.1:8000
```

从输出复制本次分配的 `https://....trycloudflare.com` 地址，打开它的 `/v1/health`，成功后把 App 的 Base URL 改为该地址并保留末尾 `/`。不要使用乙之前的临时域名，它仍指向乙电脑。

后端终端和隧道终端都要保持运行。只重启 Python 后端而不重启隧道，入口通常继续使用；隧道重开可能换域名，换后须更新 App 地址。这是临时联调入口，不是固定生产域名或云主机。若尚未安装 `cloudflared`，先走本机/局域网，不影响前面的验证。

## 8. 跑一次真实业务冒烟

在项目根目录打开新 PowerShell，填写项目路径。下列输入是单活动合成测试，会真实调用模型和地图、消耗少量团队额度；不要循环执行：

```powershell
$Project = 'D:\projects\suibian'
Set-Location -LiteralPath $Project
New-Item -ItemType Directory -Force -Path '.\.state' | Out-Null
$requestPath = Join-Path $Project '.state\startup-parse-request.json'
$request = @{
    text = '明天上午十点前到中国国家博物馆参观，从天安门出发，步行。'
    now = (Get-Date).ToString('yyyy-MM-ddTHH:mm:sszzz')
    city_adcode = '110100'
} | ConvertTo-Json
[System.IO.File]::WriteAllText($requestPath, $request, [System.Text.UTF8Encoding]::new($false))
.\.venv\Scripts\python.exe scripts/deploy_smoke.py http://127.0.0.1:8000 --login --parse-file $requestPath
```

按提示输入第 5 节创建的普通账号，密码隐藏输入。工具不自动注册、不输出 token。成功应看到健康检查、推演、解析草案通过，最终显示“真实部署与录入链路冒烟通过”。

样例按中国地点编写，Windows 的日期/时区应与本次计划一致；异地时区测试请换成相应的真实单城安排。只运行 `--login` 而不传 `--parse-file`，只能验证基础服务和推演，不验证真实录入。不要加 `--allow-mock` 来掩盖真实模式失败。

## 9. 以后怎么启动、停止、更新

以后依赖不变时，每次只需：

```powershell
$Project = 'D:\projects\suibian'
Set-Location -LiteralPath (Join-Path $Project 'server')
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 1 --no-proxy-headers --no-access-log
```

停止：在运行后端的窗口按 `Ctrl+C`，等退出后再关窗口。重启：`Ctrl+C` 停止，然后再次执行启动命令；不必重新创建虚拟环境、不必清理 `.state`。修改 `.env` 或更新提示词/代码后要重启，已运行进程不会自动刷新配置。

更新代码前先停止后端，在仓库根确认分支及未提交修改：

```powershell
Set-Location -LiteralPath $Project
git status --short
git branch --show-current
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw '拉取失败，先处理分支或本地修改，不要强制覆盖' }
.\.venv\Scripts\python.exe -m pip install --require-hashes -r .\server\requirements.lock
if ($LASTEXITCODE -ne 0) { throw '依赖更新失败' }
```

只有当前分支和本地修改都符合预期才更新。`origin` 应是包含该后端分支的仓库，拉取失败不要改用 `reset --hard`。更新后回 `server` 目录启动并复查健康接口。

## 10. 常见问题与排查顺序

| 现象 | 检查与处理 |
|---|---|
| `No module named uvicorn` | 检查使用的是项目根 `.venv\Scripts\python.exe`，并完成依赖安装 |
| `No module named app` | 当前目录错误；回到仓库的 `server` 再启动 |
| 缺少 Schema 的启动错误 | 保留完整仓库的 `schema/`；移除或纠正旧 `SCHEMA_DIR` |
| 配置仍是 MOCK 或缺 Key | 确认 `server/.env` 文件名、工作目录、旧 `deploy/.env` 和同名环境变量覆盖；不要打印整份配置 |
| `WinError 10048` / 地址已使用 | 8000 已被占用；先检查进程是不是已经启动的后端，不要反复启动或误杀其他服务 |
| `/` 返回 Not Found | 正常；检查 `/v1/health` 或 `/docs` |
| 健康正常，调用业务 401 | 在甲的新服务注册/登录，更新 token；乙服务 token 不能混用 |
| 管理员初始化失败 | 检查用户名/密码格式或同名普通账号；已有管理员密码不会被覆盖 |
| 供应商配置解密失败 | 曾复制 `providers.sqlite3` 却缺对应 `provider.key` 或匹配的 `PROVIDER_MASTER_KEY`；恢复匹配备份，不要删库碰运气 |
| 模型/天气/地图失败 | 健康检查不等于供应商实际可用；检查网络、配置、额度和控制台访问限制，保留错误码给乙；不要发 Key |
| 手机访问不到 | 先在手机浏览器测健康，再检查同网、实际 IPv4、防火墙及 App Base URL |
| 解析 200 但没有计划 | 看 `questions`，可能缺信息、超时、额度或路线失败；不能把 200 直接当完成 |

查看 8000 端口占用，以下命令只读，不停止进程：

```powershell
Get-NetTCPConnection -LocalPort 8000 -State Listen -ErrorAction SilentlyContinue |
    Select-Object LocalAddress, LocalPort, OwningProcess
```

把结果中的 PID 代入 `Get-Process -Id 实际PID` 查看。若确认是先前启动的后端，优先回它的终端 `Ctrl+C`；不要按不明 PID 结束进程。

## 11. 哪些文件必须保留

| 文件/目录 | 作用 |
|---|---|
| `server/.env` | 甲本机运行配置与团队凭据，Git 忽略 |
| 仓库根 `.state/auth.sqlite3` | 甲主机的账号、密码哈希、会话摘要；删掉后原账号/会话丢失 |
| `.state/providers.sqlite3` | 通过管理员入口保存的加密供应商配置；已保存内容优先于相应 `.env` 值 |
| `.state/provider.key` 或独立 `PROVIDER_MASTER_KEY` | 上述配置的解密密钥，备份时与数据库配对保管 |
| `.state/budgets.sqlite3` | 当日额度计数 |
| `schema/` | 运行需要的共享契约和示例资源 |

日常重启和拉取代码不删除 `.state`。需要备份时先停止后端，再复制这些状态文件，避免运行中直接拷贝出不一致状态。首次独立搭建使用甲自己的新状态目录即可；如果要迁移乙的既有账号/配置，另行协调完整状态迁移，不能只拿一个数据库文件。

`.env`、`.state`、密钥都不进 Git、不放进 APK。手机本地的计划依旧由甲的 Android 客户端保存，本机后端没有自动跨设备同步计划的接口。

## 12. 启动验收

- [ ] 已使用甲自己的 Python 3.12 虚拟环境安装锁定依赖。
- [ ] `.env` 位于 `server/.env`，真实模式开启，状态与 Schema 路径属于甲电脑。
- [ ] 后端窗口持续运行，本机健康检查的 Schema 和 config 均为 ok。
- [ ] 甲主机创建自己的账号，App 已清除旧服务器 token 并重新登录。
- [ ] 设备使用正确 Base URL，手机/模拟器能访问健康接口。
- [ ] 实际解析草案、推演和失败提示通过；后续按[甲方联调交接](甲方联调交接.md)验收刷新、重排和真机功能。

本手册只涉及甲主机部署及运行，不新增业务功能。不要把“服务已启动”“健康检查通过”“真实供应商链路通过”“Android 真机全部功能通过”当成同一层验收。
